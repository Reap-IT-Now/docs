Use the REAP API to work with network inventory, topology, incidents, configuration history, integrations, and runbooks. Browse the endpoint reference for request parameters, authentication requirements, and response schemas.

<Info>
This reference describes the public API contracts, version 1.3.0, captured on September 15, 2026. Endpoint availability depends on your REAP deployment and permissions. Confirm the base URL and enabled capabilities with your REAP contact before integrating.
</Info>

## Start with a read request

To make your first request, you need your REAP API base URL, an organization ID, and credentials with permission to read device inventory.

```bash
export REAP_BASE_URL="https://YOUR_REAP_API_HOST/v1"
export REAP_ORG_ID="YOUR_ORGANIZATION_ID"
export REAP_API_KEY="YOUR_API_KEY"

curl --request GET \
  --url "${REAP_BASE_URL}/orgs/${REAP_ORG_ID}/devices?limit=10" \
  --header "X-Api-Key: ${REAP_API_KEY}" \
  --header "Accept: application/json"
```

Replace the placeholders with your environment details. The contract defines a successful device list response as an `items` array with pagination information in `meta`. Use the endpoint schema to inspect the returned fields.

## Authentication

| Credential | Request header | Use |
| --- | --- | --- |
| API key | `X-Api-Key: YOUR_API_KEY` | Organization-scoped integrations and automation, where supported by the endpoint. |
| Bearer token | `Authorization: Bearer YOUR_ACCESS_TOKEN` | Requests using a user or session access token. |

An API key is not a bearer token. Check each endpoint's authorization section: some operations accept only bearer tokens or use an integration-specific credential.

API key secrets are returned only when created. Store them securely and avoid including them in URLs or logs. Your assigned roles determine what you can access.

## Organization and resource IDs

Most resources are scoped through `/orgs/{orgId}`. Use UUID identifiers in request paths and resource references. Display names can change and should not be used in place of resource IDs. A slug is a separate human-readable identifier where the endpoint supports it.

## Pagination

Many collection endpoints accept `limit`, `after`, and `before`. The shared contract defaults to 50 results and permits up to 200; check the specific endpoint for exceptions. Follow the pagination information returned in `meta` or the `Link` header when supplied. An omitted `meta.exactTotal` means the total is unknown.

## Updates and error handling

Where required, retrieve the resource's `ETag` and send it in `If-Match` when updating or deleting. A `412` response indicates a version mismatch. Check the endpoint parameters for the exact requirement.

| Status | Meaning |
| --- | --- |
| `400` | The request failed validation. |
| `401` | Credentials are missing, invalid, or expired. |
| `403` | Your credentials do not permit this operation. |
| `404` | The requested resource was not found. |
| `409` | The request conflicts with the current resource state. |
| `412` | A conditional request did not match the current resource version. |
| `429` | A rate limit was reached; follow `Retry-After` when supplied. |

Inspect the response body for details and retain `X-Request-Id` when supplied for troubleshooting. Individual endpoints may define additional status codes or response formats.
