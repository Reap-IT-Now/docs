A runbook is a reusable procedure for network work: the checks to perform, the decisions to make, and the result to report. In REAP, you describe that procedure in natural language and compile it into a saved, reviewable version.

Create the procedure once, then run that version again with different device or site inputs. Runbooks separate the task from vendor-specific commands, so the same procedure can be reused across supported vendors when the required operations are available. This helps your team apply the same checks consistently without maintaining a separate checklist for each platform.

## What you can do

- **Turn a team's procedure into repeatable work.** Describe the task, required evidence, decision points, and expected output. REAP turns those instructions into steps you can review before publishing.
- **Reuse the procedure with a new scope.** Supply the inputs for each execution while keeping the reviewed version of the procedure.
- **Run on demand or on a schedule.** Use one procedure for an individual investigation or a recurring check.
- **Review what happened.** Follow execution progress and inspect the report, step outcomes, and supporting evidence.

For portability, describe the outcome you need and make device or site selections inputs to the runbook. A procedure tied to a named device, vendor-specific command, or platform-only feature needs review before you reuse it elsewhere.

## Example: a consistent interface check

You could describe a runbook like this:

> For the selected devices, collect interface status, identify interfaces that are administratively enabled but operationally down, and produce a report with the device, interface, finding, and supporting evidence. Do not change configuration.

The value is the reusable check and report. After reviewing and testing it, your team can run the same procedure for another supported device group by changing the inputs.

## How to use Runbooks

<Note>
  **Draft guide.** The functionality is grounded in the product source. Validate these steps against your deployed REAP version before publishing this guide to customers.
</Note>

Choose a clear task and confirm that REAP can reach the target devices and perform the required operations.

### Create and publish

1. Open **Runbooks** and start a **New Runbook**.
2. Enter a title and **Natural-language instructions**. Describe the task, inputs, expected result, and any restrictions.
3. Select **Save runbook**. Review the **Saved Template Preview**, including parameters, steps, assumptions, missing inputs, and validation diagnostics.
4. Select **Open saved runbook** and inspect the selected version's **Instructions**, **Compiled** steps, and **Diagnostics**.
5. Resolve the issues identified during review, then select **Publish version** when the version is ready.

Publishing makes the selected version available to run. It does not start an execution.

### Run and review

1. Select the runbook in **Library** and check its version and required inputs.
2. Supply the execution inputs and verify the target scope.
3. Choose **Run once**, or **On a schedule** for recurring work. Complete any approval requested by the workflow.
4. Open **Executions** and review the status, report, and evidence. Use a controlled initial scope before applying a new procedure more broadly.
5. For recurring work, review **Schedules**, including the selected version, inputs, and timezone.

A started execution is not a completed task. Check partial or failed steps and confirm that the report covers the intended targets.
