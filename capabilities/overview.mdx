REAP helps you understand your network, investigate questions, and make operational work repeatable. Each capability guide starts with what the feature does and how it helps, followed by instructions for using it.

| What you need to do | Capability | How it helps |
| --- | --- | --- |
| Understand what is in the network | [Inventory and topology](/capabilities/inventory-and-topology) | Find devices and explore the relationships and context available around them. |
| Ask a network question | [Chat](/capabilities/chat) | Use natural language to explore network data, gather supported evidence, and ask follow-up questions. |
| Investigate an incident | [Incidents](/capabilities/incidents) | Bring incident context, available evidence, ownership, and linked tickets together. |
| Repeat a procedure consistently | [Runbooks](/capabilities/runbooks) | Create a procedure once and reuse the saved version across supported devices and vendors. |
| Validate a network change | [Change Management](/capabilities/change-management) | Turn a proposed change into a plan, capture before-and-after evidence, and assess the result. |
| Review vulnerability exposure | [CVEs](/capabilities/cves) | Connect vulnerability signatures to device versions and relevant configuration evidence. |
| Understand configuration changes | [Running config](/capabilities/configuration-history) | Inspect timestamped snapshots and compare what changed. |

## Choose a starting point

If you are new to REAP, follow the [quickstart](/getting-started/quickstart) to connect a site and ask your first network question.

If your network is already connected, start with [Chat](/capabilities/chat) and a question about a known site or device. Use [Inventory and topology](/capabilities/inventory-and-topology) when you need to establish the scope first.

For repeatable work, capture the procedure in a [runbook](/capabilities/runbooks). For an upcoming change, use [Change Management](/capabilities/change-management) to plan the evidence you need before implementation.

## Work from Slack

The [Slack integration](/integrations/slack) brings supported network questions, incident actions, and runbook interactions into your team's workspace. Its ServiceNow incident workflow requires a configured ServiceNow integration.
