Device credentials let REAP authenticate to your network devices. An assignment tells REAP where a saved credential applies. Configure both before discovery so the intended devices can be reached with the right authentication.

This guide covers the **CLI (SSH)** and **SNMP v3** setup shown in the discovery walkthrough.

## Before you begin

- Create the [site](/deployment/sites-and-discovery#create-a-site) and prepare its [cluster and connector](/deployment/clusters-and-connectors).
- Have credentials already configured on the target devices, with the required device privileges.
- Identify which sites and device groups should use each credential.

## Add a CLI (SSH) credential

1. Open **Credentials**, select the **Credentials** tab, and select **\+** to open **New credential**.
2. Enter a recognizable **Display name** and set **Kind** to **CLI (SSH)**.
3. Under **CLI (SSH) details**, enter the device **Username** and **Port**. The form defaults to port **22**; use the port configured on your devices.
4. Under **Primary authentication**, choose **Password** and enter the device password. The form also offers **SSH private key** and **Credential Store**; choose the method approved for your environment.
5. If your devices require an enable password, select **Provide enable password** and supply it.
6. Select the save icon in the top-right corner.
7. Repeat for device groups that use different authentication.

## Add an SNMP v3 credential

1. Create another **New credential**, enter its **Display name**, and set **Kind** to **SNMP v3**.
2. Enter the SNMP v3 **Username** and **Port**. The default port is **161**.
3. Set **Engine ID** and **Context name** if your device configuration requires them.
4. Choose the **Security level** that matches the devices.
5. For a level requiring authentication, supply the matching **Auth protocol** and **Auth password**.
6. For a level requiring privacy, supply the matching **Privacy protocol** and **Privacy password**.
7. Select the save icon.

The walkthrough uses **authPriv**, **SHA**, and **AES-128**. These are example settings; the values must match the SNMP user configured on your devices.

## Assign credentials to the intended scope

<Steps>
  <Step title="Create an assignment">
    Select **Credentials > Assignments**, then **\+**. Enter a **Name** and select the saved **Credential**.
  </Step>
  <Step title="Enable it and choose a scope">
    Keep **Assignment enabled** selected. For a first assignment with no competing matches, retain the default **Priority** of **100**.

    Under **Scope**, choose where it should apply:

    | Scope | Use it for |
    | --- | --- |
    | **Specific sites** | Select the sites whose devices should use this credential. |
    | **Exact devices** | Select existing devices for a device-specific assignment. |
    | **Entire organization** | Apply the assignment across the organization, subject to any filters. Use only when that breadth is intended. |
  </Step>
  <Step title="Add matching filters">
    Use **Filters (optional)** to narrow the assignment with hostname patterns, required labels, **Vendors any**, or **Models any**.

    For example, separate SSH credentials for Arista and Palo Alto devices can each have an assignment with the corresponding vendor selected. A shared SNMP v3 credential can have both vendors selected if it is configured on both groups.
  </Step>
  <Step title="Save and review coverage">
    Select the save icon. Confirm the credential, scope, and filters in the **Assignments** table.

    Check that every intended device group has the required protocol credentials. Vendor filters exclude devices that do not match; the example assignments are not a complete credential plan for every network.
  </Step>
</Steps>

Avoid unintentionally overlapping assignments during initial setup. If multiple assignments match the same devices, confirm the precedence behavior for your deployed version before changing priorities.

## Verify authentication during discovery

[Start a scoped discovery run](/deployment/sites-and-discovery#create-a-discovery-job) and inspect its events and Inventory results. If authentication fails, check:

- The credential kind, username, port, and authentication values match the device.
- The assignment is enabled and its scope and filters include the target.
- The device account has the privileges needed for the operation.
- The connector can reach the device over the relevant protocol.
- SNMP v3 security level, authentication, and privacy settings match on both sides.

Do not paste passwords, private keys, or tokens into support requests. Share the credential name, affected scope, error, and time without secret values.

## Other credential types

The credential form also includes **gNMI**, **SNMP v2c**, and **API (REST)**. Their presence does not establish support for every device or collection workflow; confirm the requirements for your intended use.
