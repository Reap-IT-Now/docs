Open **Credentials** to manage device authentication. Choose a credential type that matches the protocol and permissions required by your collection workflow.

## Credential types

| Type in the UI | Intended use |
| --- | --- |
| CLI (SSH) | Device CLI authentication using the supported password or key options. |
| gNMI | Authentication and TLS configuration for gNMI access. |
| SNMP v2c | Community-based SNMP authentication. |
| SNMP v3 | SNMP user authentication and privacy settings. |
| API (REST) | API key, basic authentication, bearer token, or mTLS configuration. |

The availability of a credential type does not by itself establish support for every device or collection workflow.

## Setup workflow

1. Open **Credentials** and start a **New credential**.
2. Give it a recognizable name and choose its type.
3. Enter the authentication material required by the form.
4. Save the credential.
5. Apply the appropriate assignment for the intended device or discovery scope.
6. Run a scoped collection or discovery check and review the result.

Use credentials approved for the intended task. Confirm the assignment workflow and required device privileges before publishing the final procedure.

## Troubleshooting

If authentication fails, check the protocol, credential assignment, account permissions, and network reachability. For certificate-based authentication, also check certificate validity and trust configuration.

Do not paste passwords, private keys, or tokens into a support request. Share the error, time, affected scope, and credential name without its secret values.
