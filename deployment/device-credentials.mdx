Device credentials let REAP authenticate to your network devices. An assignment tells REAP where a saved credential applies. Configure both before discovery so the intended devices have the right authentication.

This guide covers **CLI (SSH)** and **SNMP v3**. Match the values to authentication already configured on your devices.

## Before you begin

- Create the [site](/deployment/sites-and-discovery#create-a-site) and prepare its [cluster and connector](/deployment/clusters-and-connectors).
- Have device accounts with the privileges required for discovery and collection.
- Identify which sites and device groups should use each credential.

## Add a CLI (SSH) credential

1. Open **Credentials > Credentials** and select the **plus (+)** icon to open **New credential**.
2. Complete the fields below and set **Kind** to **CLI (SSH)**.
3. Choose the appropriate **Primary authentication** method and supply its fields.
4. If needed, select **Provide enable password** and enter **Enable password**.
5. Select the **Save credential** disk icon at the top right.
6. Repeat for device groups that use different authentication.

| Field | What to enter or choose |
| --- | --- |
| **Display name** | A recognizable credential name, such as `London switches SSH`. |
| **Description** | Optional. Describe which device accounts or groups use this credential. |
| **Kind** | **CLI (SSH)**. |
| **Username** | The SSH username configured on the devices. |
| **Port** | The devices' SSH port. The form defaults to **22**. |
| **Labels** | Optional key and value pairs to help organize the credential. |
| **Provide enable password** | Select only if the devices require an enable password, then enter it in **Enable password**. |

Under **Primary authentication**, choose one method:

| Method | Fields to complete |
| --- | --- |
| **Password** | Enter the device account's password in **Password**. |
| **SSH private key** | Paste the complete PEM key into **Private key (PEM)**. If the key is encrypted, enter its passphrase in **Passphrase (optional)**. |
| **Credential Store** | Select an existing approved store from **Credential store**. If none is available, have your administrator configure it in the **Credential Store** tab before using this method. |

## Add an SNMP v3 credential

1. In **Credentials > Credentials**, select the **plus (+)** icon again.
2. Enter **Display name**, an optional **Description** and **Labels**, and set **Kind** to **SNMP v3**.
3. Complete the protocol fields below, using the SNMP user configuration on the devices.
4. Select the **Save credential** disk icon.

| Field | What to enter or choose |
| --- | --- |
| **Username** | The SNMP v3 username configured on the devices. |
| **Port** | The devices' SNMP port. The form defaults to **161**. |
| **Engine ID (optional)** | Enter the engine ID if required by your device configuration. |
| **Context name (optional)** | Enter the SNMP context if required by your device configuration. |
| **Security level** | Match the device user: **noAuthNoPriv** needs neither authentication nor privacy settings; **authNoPriv** needs authentication; **authPriv** needs both. |
| **Auth protocol** and **Auth password** | When authentication is required, select the matching authentication protocol and enter the user's authentication password. |
| **Privacy protocol** and **Privacy password** | When privacy is required, select the matching privacy protocol and enter the user's privacy password. |

## Assign credentials to the intended scope

Saving a credential does not assign it to devices. Create an assignment for each credential and device group that needs it.

<Steps>
  <Step title="Create the assignment">
    Open **Credentials > Assignments**, then select the **plus (+)** icon.

    | Field | What to enter or choose |
    | --- | --- |
    | **Name** | A recognizable assignment name, such as `London switch SSH access`. |
    | **Description** | Optional. Explain why this assignment exists or which devices it covers. |
    | **Credential** | Select the saved credential you want to apply. |
    | **Priority** | For a first assignment without competing matches, retain the default **100**. Confirm precedence for your deployed version before changing priorities on overlapping assignments. |
    | **Assignment enabled** | Keep selected so the assignment is enabled. |
  </Step>
  <Step title="Choose the scope">
    Under **Scope**, select one option and complete its selection.

    | Scope | What to select |
    | --- | --- |
    | **Specific sites** | Select the checkboxes for the sites whose devices should use this credential. This is a useful starting scope for your first site. |
    | **Exact devices** | Select existing devices for a device-specific assignment. Devices must already be available in the list. |
    | **Entire organization** | Apply across the organization, subject to any filters. Choose it only when this breadth is intended. |

    Review **Current selection** before continuing.
  </Step>
  <Step title="Set optional filters">
    Leave filters empty unless you need to narrow the scope. Use the exact values or patterns that match your intended devices.

    | Filter | What to enter or choose |
    | --- | --- |
    | **Hostname regex** | A regular expression, such as `^core-`, for matching hostnames. |
    | **Hostname prefixes** | Comma-separated prefixes, such as `edge-,agg-`. |
    | **Hostname suffixes** | Comma-separated suffixes, such as `-01,-02`. |
    | **Required labels (key=value per line)** | One required device label per line, such as `role=edge`. |
    | **Vendors any** | Select the vendors that should use this credential. |
    | **Models any** | Enter matching model names separated by commas. |

    For example, separate SSH credentials for Arista and Palo Alto devices can each have an assignment with the corresponding vendor selected. A shared SNMP v3 credential can cover both vendors if that same SNMP user configuration exists on both groups.
  </Step>
  <Step title="Save and review coverage">
    Select the **Save assignment** disk icon at the top right. Confirm the credential, scope, and filters in the **Assignments** table.

    Repeat as needed so every intended device group has the required protocol credentials. Check that filters do not unintentionally exclude devices.
  </Step>
</Steps>

## Verify authentication during discovery

[Start a scoped discovery run](/deployment/sites-and-discovery#create-a-discovery-job) and inspect its events and Inventory results. If authentication fails, check:

- The credential kind, username, port, and authentication values match the device.
- The assignment is enabled and its scope and filters include the target.
- The device account has the required privileges.
- The connector can reach the device over the relevant protocol.
- SNMP v3 security level, authentication, and privacy settings match on both sides.

Do not paste passwords, private keys, or tokens into support requests. Share the credential name, affected scope, error, and time without secret values.

## Other credential types

The credential form also includes **gNMI**, **SNMP v2c**, and **API (REST)**. Confirm the requirements for your intended device and collection workflow before configuring those types.
