A connector gives REAP access to your network. A cluster groups connectors and connects them to sites, so discovery can use the right network path. Creating a connector record in REAP and deploying its software are separate steps.

This guide covers a connector hosted on **AWS EC2** for an **OnPrem** site. Use the names, addresses, and deployment settings for your own environment.

## Before you begin

- [Create your site](/deployment/sites-and-discovery#create-a-site) in the correct organization.
- Complete the [requirements checklist](/getting-started/requirements).
- Obtain the approved REAP AMI, sizing, networking, and instance access settings for your AWS environment.

## Create a cluster and attach the site

<Steps>
  <Step title="Create the cluster">
    Open **Connectivity & Sites > Clusters**. Select the **plus (+)** icon to open **Create Cluster**.

    | Field | What to enter or choose |
    | --- | --- |
    | **Name** | Required. Enter a recognizable cluster name, such as `London cluster`. |
    | **Description** | Optional. Describe the network or operational purpose this cluster serves. |
    | **Labels** | Optional. Select **+ Add label**, enter a key and value, and repeat for additional labels. For example, key `environment`, value `production`. Select **Remove** beside a row to remove it. |
    | **Enable internal inspection endpoints** | Leave unchecked for normal setup. This permits on-device debug REST endpoints for secrets and credentials. Enable only as part of an approved troubleshooting procedure. |

    Select **Create Cluster**, then open the new cluster.
  </Step>
  <Step title="Attach your site">
    In the cluster drawer, select **Sites**. Choose the existing site from the dropdown, then select **Attach site**.

    Confirm that the site appears in the table. Selecting the dropdown value alone does not attach it. **Detach** removes an existing attachment; use it only when intentionally changing the site's connectivity.
  </Step>
  <Step title="Verify the association">
    Return to **Connectivity & Sites > Sites**, open your site, and select **Clusters**. Confirm the intended cluster is listed.

    A cluster can show **active** while it has no connectors. The site attachment and cluster status do not mean a connector has been deployed or devices have been discovered.
  </Step>
</Steps>

To edit a cluster later, open **Connectivity & Sites > Clusters**, select the cluster, and open **Details**. Update **Name**, **Description**, **Labels**, or the inspection setting, then select the **Save cluster** disk icon at the top right. The summary shows **Status**, **HA state**, **Connectors**, **Internal inspection**, and **Updated**; these are reported values, not fields you enter.

## Create the connector record

1. Open your cluster and select its **Connectors** tab.
2. Select the **plus (+)** icon to open **Create Connector**.
3. Complete the fields below, then select **Create Connector**.
4. Open the new connector. Its initial status can be **registering** until the deployed software connects.

| Field | What to enter or choose |
| --- | --- |
| **Name** | Required. Enter a name that identifies the connector host, such as `london-connector-01`. |
| **Cluster** | Confirm the cluster you opened. It is preselected and locked when creating from that cluster. If you instead start from **Connectivity & Sites > Connectors > plus (+)**, select the intended cluster. |
| **Description** | Optional. Identify the connector's host or purpose so your team can recognize it later. |
| **Labels** | Optional. Select **+ Add label** and enter each key and value. Use **Remove** to remove a label row. |

To edit an existing connector, open its **Details** tab. Update **Name**, **Cluster**, **Description**, or **Labels**, then select the **Save connector** disk icon at the top right. Check the cluster selection carefully when changing an existing connector's assignment.

## Download the bootstrap bundle

Open the connector, select **Bootstrap**, and choose the format required by your deployment method.

| Control | When to use it |
| --- | --- |
| **Cloud-init** | Download the connector's cloud-init bundle. Use this for the AWS EC2 user data procedure below. |
| **JSON** | Download the JSON bootstrap bundle when your approved deployment procedure calls for that format. |
| **Reset enrollment** | An enrollment recovery action, not a download or a normal installation step. Use only when intentionally re-enrolling a connector and following the recovery procedure. Read the confirmation before proceeding. |

Treat the downloaded bundle as sensitive deployment data. Use the bundle for the connector you are deploying and keep it out of documentation and support messages.

## Deploy the connector in AWS EC2

<Steps>
  <Step title="Launch the approved REAP AMI">
    In the intended AWS account and region, open the REAP-provided AMI and select **Launch instance from AMI**.

    Enter an instance name and use the instance type, key pair or access method, and storage specified in your approved deployment instructions.
  </Step>
  <Step title="Configure networking">
    In **Network settings**, select the approved VPC, subnet, IP assignment, and security group configuration. Confirm the required routes to REAP and the target device management network, including return routing.
  </Step>
  <Step title="Supply the connector's cloud-init data">
    Open **Advanced details > User data**. Supply the contents downloaded through **Bootstrap > Cloud-init** for this connector, using the method specified in your deployment instructions. Preserve the file contents.
  </Step>
  <Step title="Launch and check registration">
    Review the settings and select **Launch instance**. After the instance starts, return to **Connectivity & Sites > Connectors** and select the refresh icon.

    Open the connector's **Details** tab. Confirm **Status** is **online**, **Last seen** is recent, and **Cluster** is correct. **Version** identifies the software reported by the connector. If it remains **registering**, use the checks below before starting discovery.
  </Step>
</Steps>

## Verify readiness

- The connector VM is running and used the bundle for the intended connector.
- The connector reports **online**, has recent **Last seen** information, and belongs to the intended cluster.
- The site is attached to that cluster, and the cluster's **Connectors** tab lists the deployed connector.
- The connector can reach REAP and the target management addresses over the required protocols, with working return routes.

A connector being **online** confirms its reported connection to REAP. Verify device reachability and authentication separately. A site's **Healthy** label alone does not establish discovery coverage.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Connector stays in registering | Correct AMI and connector-specific cloud-init data, instance startup, and the connector-to-REAP network path. |
| Cluster is active but has no connectors | Create a connector record, deploy it, and verify that it appears in the cluster's **Connectors** tab. |
| No cluster appears in the discovery form | Open the intended cluster's **Sites** tab and verify the site attachment. The job inherits this association. |
| Connector is online but devices are unreachable | Routes, security groups, device-side access rules, target management addresses, and return routing. |
| Devices respond but authentication fails | Check [device credentials and assignments](/deployment/device-credentials). |

If the issue remains, [contact support](/support/contact) with the connector identifier, status, error, and time, without secret values or bootstrap material.
