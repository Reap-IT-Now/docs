REAP connects network data to investigation and operational workflows. Start with one site, discover its devices, and use that context to ask questions, investigate incidents, or prepare repeatable checks.

## The building blocks

| Concept | What it does |
| --- | --- |
| Organization | Keeps your network resources, access, and integrations in a workspace. Select the correct organization before setup. |
| Site | Represents a network location or scope, such as a branch or data center. |
| Cluster | Groups connectors and attaches them to a site. Discovery uses the cluster associated with that site. |
| Connector | Runs in your deployment environment and provides connectivity to the network. Creating its REAP record and deploying the software are separate steps. |
| Credential | Stores the authentication configuration for a device protocol, such as CLI (SSH) or SNMP v3. |
| Credential assignment | Determines where a saved credential applies, using a scope and optional device filters. |
| Discovery job | Saves the site, targets, and schedule for discovery. |
| Discovery run | Executes a discovery job and records progress, results, and errors. |
| Integration | Connects REAP to another system, such as Slack or ServiceNow. |

## How setup fits together

Create a site, attach a connector cluster, and deploy a connector in that cluster. Add device credentials and assignments, then create a discovery job and start a run.

After discovery, check the site's Inventory before using the collected information in Chat or another capability. A saved job is configuration; a completed run is evidence that discovery executed. Confirm the expected devices in Inventory even when the run reports **succeeded**.
